# VP-008 implementation plan

Accepted baseline main 6b7af2b. No Settings, navigation, auth callback or product-spec changes.

1. Receipt-owned migration creates private image bucket, owner-readable receipt records and a durable leased queue. Browser database writes are denied; the Go API performs privileged mutations only after Foundation verifies the caller UUID. Database functions scope every operation by verified owner and version, enforce quotas and atomically deduplicate upload/retry/job completion.
2. Go Receipt module provides bounded upload, private image retrieval, list/get, versioned review/save and retry endpoints. Foundation's existing GET middleware remains the default; a narrowly parameterized method allowlist adds authenticated Receipt mutation handling. API and worker credentials remain server-only.
3. A separate bounded Receipt worker claims leased jobs. Provider-neutral Extractor returns normalized advisory Proposal. Owner-approved Gemini 3.5 Flash-Lite adapter validates structured output; AWS adapters can implement the same interface later. No paid fallback. Explicit fake mode only for development/test. Missing key/access is actionable; a successful real synthetic adapter smoke is recorded separately from fake tests.
4. Backend validates review input and computes whole-item draft previews using integer minor units, explicit proportional/equal methods and participant inclusion. Largest-remainder distribution orders ties by participant ID; zero-weight proportional amounts and nonzero receipt-level discounts block verification until the owner resolves them. No finalized states or receivables.
5. Receipt-specific route/components implement image upload, processing/retry, owner corrections, participants/assignments and persisted draft preview. Existing shell is consumed unchanged.
6. Test money/proposals/provider faults/limits/worker behavior, two-owner storage/RLS and stale-version contracts in disposable infrastructure, and DOM flow. Document all exact checks and missing live/visual evidence. Push task branch and request independent review; never self-approve.
