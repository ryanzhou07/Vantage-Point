`VP-004`

## Owner
Foundation Agent — current authentication vertical, with explicit shared UI extraction and independent Integration/Review.

## Purpose
Make the current auth frontend easy to maintain and reuse, and improve the sign-in presentation. The owner requested this after reviewing VP-003's compressed `page.tsx`.

## Scope
- Reformat the existing frontend auth slice into readable imports, handlers, effect cleanup, JSX and logical blocks.
- Keep App Router pages focused on composition; extract auth state/control into a clearly named auth hook/controller and UI into focused components.
- Extract shared presentation primitives used by the auth and callback views (for example actions, surfaces and status/error messages) with typed props and accessible semantics, suitable for reuse by the later Dashboard.
- Modernize the sign-in area with coherent Vantage-Point branding, clear hierarchy, intentional spacing, a recognizable Google action, responsive layout, and useful loading/error/retry/signed-in/sign-out states.
- Document component ownership and update relevant frontend tests and local visual verification evidence.

Primary paths: `apps/web/app/page.tsx`, auth callback page, existing frontend auth helpers, feature auth components/hooks, shared UI components, relevant styles/frontend tests, and component documentation. This task may move existing auth UI state/control without changing its tested behavior.

## Out of Scope
Backend/auth provider changes, schema/migrations, new sign-in methods, permissions/session/PKCE semantics, Dashboard features, Banking/Receipt features, new frameworks/component libraries, production deployment, and an unused comprehensive design system.

## Requirements
1. Follow PROJECT.md §§4–5, 29, 36 and DESIGN.md §§2, 5–7, 26, 39, 44, 47.
2. Replace compressed multi-statement handlers and nested one-line JSX with readable blocks. Add blank lines between logical sections; break long JSX props onto separate lines. Formatting must improve scanning without unnecessary fragmentation.
3. Pages compose named components and auth control rather than containing the whole interaction/UI in one function. Reusable UI primitives accept explicit typed props and contain presentation behavior only; provider-specific auth logic stays in the auth feature layer.
4. Preserve Google PKCE, callback restrictions, profile loading, sign-out, cancellation/cleanup, busy/deduplication, retry/error behavior and public contracts verified by VP-003.
5. Retain keyboard access, visible focus, meaningful button labels, loading/alert semantics, adequate touch targets and contrast. Mobile layout must have no horizontal overflow.
6. Modernization stays within the current product and stack; no invented financial figures, feature promises, or unavailable functionality in sign-in content.
7. Document shared component interfaces for Dashboard reuse, keeping abstractions proportional to actual repeated UI needs.
