# VP-015a — Receipt split-session lifecycle (create, 5-minute expiry, invalidate)

## Status
`ACTIVE`

## Owner
Receipt Agent (Integration/Review separate)

## Purpose
Let a receipt owner open a temporary split session that issues a share token and automatically closes after 5 minutes, so no long-lived session remains.

## Scope
- Migration `split_sessions` per DESIGN.md (id, receipt_id, token_hash, status, created_at, expires_at, invalidated_at) with RLS for the owner.
- Owner API: create session, get status, close now, extend/restart (new `expires_at`).
- Raw token returned once at creation; only a hash is stored.
- Expiry enforced server-side on every participant-token check (`now() >= expires_at` rejects); no reliance on a client or a timer.
- Duration from config `SPLIT_SESSION_TTL` (default `5m`, bounded, e.g. 1m–60m).
- Session also becomes invalid when the receipt is finalized.

## Out of Scope
QR rendering, participant join UI, realtime, claims/allocations, finalization itself.

## Dependencies
VP-008 COMPLETED. Foundation identity contract.

## Requirements
1. Expiry affects access only; receipt, items and prior submissions stay stored.
2. Owner authorization from the verified Foundation context; a receipt ID alone never authorizes.
3. One active session per receipt; creating another invalidates the previous.
4. Token is high-entropy and compared by hash in constant time; never logged.
5. Rate limit session creation.

## Acceptance Criteria
- [ ] Token valid before expiry, rejected at and after `expires_at` (injected clock).
- [ ] Previous token rejected after a new session is created.
- [ ] Non-owner cannot create, read or close another user's session.
- [ ] Raw token never persisted or logged.
- [ ] Migration applies on a clean database; applied migrations untouched.

## Testing Requirements
Migration, RLS, authorization, expiry-with-fake-clock, token-hash and rate-limit tests.

## Shared Resource Impact
Identity: reads only. Others: NO.

## Contract Impact

## Security Considerations
Bearer token handling per DESIGN.md; participants get only receipt-scoped access.

## Financial Correctness Considerations
