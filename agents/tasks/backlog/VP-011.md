# VP-011 — User-scoped normalized financial account service

## Status
`BACKLOG` — owner clarified “user account service” means a Banking service attached to the existing signed-in Vantage-Point user. Depends on Teller connection lifecycle.

## Proposed owner
Banking Agent, with separate Integration/Review; Dashboard consumes the approved contract only in a later task.

## Purpose
Expose normalized Vantage-Point financial accounts associated with a user’s institution connections. The browser reads this service and never calls Teller directly.

## Proposed first scope
- Discover and persist accounts belonging to an owner-authorized Teller connection.
- Return a user-scoped list of account identity/display fields and current/available balances only if approved; all monetary values use exact integer minor units and currency codes.
- Keep an institution connection distinct from each financial account and use stable normalized Vantage-Point identifiers.
- Enforce authorization in API and database; test two-user isolation, provider failures, missing/closed accounts, duplicate sync, and exact balance normalization.

## Dependencies and owner decisions
- VP-010 COMPLETED.
- Confirm whether first read scope includes balances or only account metadata. Transactions and background synchronization remain later work unless separately approved.
- Confirm refresh cadence/manual refresh and stale-data presentation before adding sync.
- Follow `PROJECT.md` Banking model and `DESIGN.md` normalization, authorization and exact-money rules. No separate microservice or canonical identity.

## Out of scope
Transactions, recurring activity, financial advice, safe-to-spend, cross-domain aggregation, and UI beyond a contract consumer authorized by a later Dashboard task.
