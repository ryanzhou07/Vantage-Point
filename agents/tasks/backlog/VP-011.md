# VP-011 — User-scoped normalized financial accounts and manual refresh

## Status
`BACKLOG` (owner decisions recorded 2026-10-28; awaiting READY approval)

## Owner
Banking Agent (Integration/Review separate)

## Purpose
Expose normalized accounts and balances for a user's connections, refreshed manually through a function built so a scheduled worker can reuse it.

## Scope
- Migration: `accounts` (id, institution_connection_id, provider_account_id, name, type, subtype, mask, currency, current_balance_minor, available_balance_minor, status, last_synced_at) with RLS via the owning connection.
- `SyncConnection(ctx, connectionID)`: idempotent, coalesces concurrent calls for one connection, upserts accounts/balances, records last_sync_attempt_at and error state, keeps last good data on provider failure.
- `POST /api/v1/banking/connections/{id}/refresh` (manual) with 5-minute per-connection cooldown; `GET /api/v1/banking/accounts`.
- Balances as integer minor units plus currency code; response includes `last_synced_at` and a stale/error indicator.

## Out of Scope
Transactions, pending/posted reconciliation, scheduled worker, webhooks, recurring activity, Dashboard UI.

## Dependencies
VP-010 COMPLETED.

## Requirements
1. Parse provider decimal strings to integer minor units with exact arithmetic; no float.
2. Cooldown and coalescing are enforced server-side regardless of frontend or cache.
3. `SyncConnection` has no HTTP dependency so a future worker calls it directly.
4. Provider failure never deletes synced data.

## Acceptance Criteria
- [ ] Balance parsing tests (negative, zero, 2-decimal, bad input).
- [ ] Concurrent refresh calls cause one provider fetch.
- [ ] Cooldown rejects a second refresh inside 5 minutes.
- [ ] User B cannot see user A's accounts.
- [ ] Provider failure keeps old balances and sets error state.

## Testing Requirements
Unit, concurrency, idempotency, isolation, migration tests with fake provider.

## Shared Resource Impact

## Financial Correctness Considerations
Integer minor units only; idempotent upserts keyed on (connection, provider_account_id); duplicate syncs must not double-count.
