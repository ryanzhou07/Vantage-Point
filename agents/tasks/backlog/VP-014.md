# VP-014 — Domain import-boundary CI check

## Status
`BACKLOG` (owner requested 2026-10-28; awaiting READY approval)

## Owner
Foundation Agent (shared CI) with Integration/Review. CI is a shared resource; review is mandatory.

## Purpose
Keep the modular monolith splittable (ADR-010) by failing CI when one domain imports another domain's internals.

## Scope
- A small backend check (Go, `go list -deps`/import graph, run from `scripts/check-backend.sh`) enforcing that packages under `services/backend/internal/{banking,receipts,dashboard}` do not import each other; all may import `internal/foundation` and `internal/platform` only through their exported APIs.
- A short allow-list file with a reason per exception.
- A negative test proving a forbidden import fails the check.
- README note on the rule.

## Out of Scope
Refactoring existing code, frontend import rules, SQL/table-access linting (a possible later task), new CI jobs beyond one step.

## Dependencies
None. Best run before VP-009a lands any Banking code.

## Requirements
1. Check fails with a clear message naming the offending import.
2. Allow-list entries need a written reason and reviewer sign-off.
3. No existing CI check is weakened or disabled.

## Acceptance Criteria
- [ ] Current main passes.
- [ ] A test fixture with a Banking→Receipts import fails.
- [ ] Runs in the existing Backend CI job in under a minute.

## Testing Requirements
Positive and negative tests of the checker; local run of `scripts/check-backend.sh`.
