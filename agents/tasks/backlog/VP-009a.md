# VP-009a — Secret source and AES-256-GCM token encryption

## Status
`BACKLOG` (owner decisions recorded 2026-10-28; awaiting READY approval)

## Owner
Banking Agent (Integration/Review separate)

## Purpose
Give Banking a backend-only way to load secrets (local files/env in development, AWS Secrets Manager in production) and to encrypt provider tokens at rest.

## Scope
- `SecretSource` interface in `services/backend/internal/banking` with `LocalSource` (files/env outside the repo) and `AWSSource` (AWS Secrets Manager, in-memory cache with short TTL).
- AES-256-GCM `Seal`/`Open` helpers: random 12-byte nonce per call, additional authenticated data = user ID + connection ID, stored key-version prefix so keys can rotate.
- Config: `TELLER_SECRET_SOURCE=local|aws`, secret names `vantage-point/<env>/teller-*`, `TOKEN_ENCRYPTION_KEY` (32 bytes) for local only.
- ADR-009 implemented; documentation of setup.

## Out of Scope
Teller client, database, API, UI, enrollment. No key rotation job. No other AWS services.

## Dependencies
ADR-009 approved by owner (new AWS SDK dependency). AWS region and secret naming confirmed (placeholder `vantage-point/<env>/teller-*`).

## Requirements
1. Keys and secrets never appear in logs, errors, API responses or Git.
2. Missing or wrong-length key fails startup closed.
3. Ciphertext opened with different AAD, key version or tampered bytes fails.
4. Local source defaults to `~/.config/vantage-point/teller/`; directory 0700, files 0600 checked at load.
5. AWS access uses the default credential chain/IAM role, never static keys in config.

## Acceptance Criteria
- [ ] Round-trip, wrong-AAD, tampered-ciphertext, wrong-key and nonce-uniqueness tests pass.
- [ ] Startup fails closed on missing/short key and on loose file permissions.
- [ ] AWS source tested with a fake client; no real AWS call in CI.
- [ ] `*.pem`/`*.key` ignored in `.gitignore`.

## Testing Requirements
Unit tests, fake AWS client, secret-scan of the diff, `go vet`, existing Security CI.

## Shared Resource Impact
Infrastructure: YES (AWS Secrets Manager dependency; ADR-009). Others: NO.

## Database Impact
NONE

## Contract Impact
NEW CONTRACT (internal Go interface only)

## Security Considerations
Highest-sensitivity task. Least-privilege IAM (GetSecretValue on the prefix only). Redact all secret values in errors.

## Financial Correctness Considerations
Not applicable.
