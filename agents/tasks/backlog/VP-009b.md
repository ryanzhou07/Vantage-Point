# VP-009b — Teller mutual-TLS provider client

## Status
`BACKLOG` (owner decisions recorded 2026-10-28; awaiting READY approval)

## Owner
Banking Agent (Integration/Review separate)

## Purpose
Provide the server-side Teller adapter that speaks to Teller over verified TLS with a client certificate.

## Scope
- Teller adapter behind a Banking-owned interface returning normalized Vantage-Point types.
- `http.Transport` with `tls.Config{MinVersion: tls.VersionTLS12, Certificates: [clientCert], RootCAs: system}`; certificate and key loaded via `SecretSource` (VP-009a) and `tls.X509KeyPair`.
- `TELLER_ENV=sandbox|development|production`; Sandbox is the default. Per-user token sent as HTTP Basic username over this client only.
- Timeouts, bounded retries with jitter, concurrency cap, response size limits.

## Out of Scope
Persistence, enrollment, accounts, balances, UI, probe. No Plaid.

## Dependencies
VP-009a COMPLETED.

## Requirements
1. Development and Production fail closed at startup if cert/key are missing, mismatched or expired.
2. Never set `InsecureSkipVerify`; never fall back to a call without the client certificate.
3. Sandbox may omit the certificate; if supplied it is used.
4. Provider structs never leave the adapter.
5. Errors are mapped to a small set of typed Vantage-Point errors with no token or cert content.

## Acceptance Criteria
- [ ] Fake TLS server accepts a call with the right client cert and rejects without it.
- [ ] Wrong server cert, expired cert and mismatched key fail.
- [ ] Retry bound and timeout verified.
- [ ] No real-bank request in CI.

## Testing Requirements
Unit and fake-TLS-server tests; manual Sandbox check recorded as evidence only.
