# VP-009 — Teller provider adapter and mutual TLS policy

## Status
`BACKLOG` — owner selected Teller.io over Plaid and asked for TLS client-certificate support plus Sandbox. Detailed task approval is still required before READY.

## Proposed owner
Banking Agent, with separate Integration/Review.

## Purpose
Add a small provider adapter/configuration boundary that can safely speak to Teller and can later support a user-owned connection flow. Teller credentials and transport remain server-side; Banking consumes normalized Vantage-Point contracts.

## Proposed scope
- Explicit Teller environment setting with Sandbox as the safe test environment.
- In Development and Production, fail closed unless a valid client certificate and matching private key are configured. Require mTLS and normal server-certificate verification; never disable TLS validation or fall back to an uncredentialed request.
- In Sandbox, client certificates are optional; if configured, verify that the TLS server validates them. Sandbox tests use simulated data only.
- Load certificate/key material only on the backend from private local configuration in development and the approved secret source in deployment. Never expose or log either value.
- Fake TLS/provider contract tests and documented setup/error handling. No real-bank Development request in CI.

## Dependency proposal
No application dependency on VP-006; local launcher support for persistent Teller configuration is a later coordination item. Use the existing Foundation identity and Banking ownership contracts. Existing provider adapter boundaries in `PROJECT.md` §§7–9 and `DESIGN.md` Banking sections remain authoritative.

## Owner decisions needed before READY
- Confirm Sandbox is used for ordinary local UI/testing and Development is opt-in for real bank data.
- Confirm where local certificate/key files will live and the approved production secret source. Do not invent a new secret service or commit credentials.
- Confirm whether this task stops at an authenticated mTLS provider client or also includes a minimal Teller connection probe.

## Sources
- [Teller API authentication](https://teller.io/docs/api/authentication/) says mTLS is required for API calls involving end-user data in Development/Production; Sandbox does not require client authentication but validates a supplied certificate.
- [Teller environments](https://teller.io/docs/guides/environments/) describes Sandbox as simulated/free and Development as real bank data.

## Guardrails
No account schema, connection persistence, transactions, user-facing Link flow, production access, real-data smoke, or new microservice in this provider-foundation task. Do not alter canonical identity or financial semantics.
