# VP-010 — Authenticated Teller connection lifecycle

## Status
`BACKLOG` (owner decisions recorded 2026-10-28; awaiting READY approval)

## Owner
Banking Agent (Integration/Review separate)

## Purpose
Let a signed-in user enroll an institution through Teller Connect, persist the connection under that user, list it, and disconnect it.

## Scope
- Migration: `institution_connections` (id, user_id -> profiles(id), provider, provider_connection_id, institution_name, status, encrypted_credential + key_version, last_sync_attempt_at, last_successful_sync_at, timestamps) with RLS `user_id = auth.uid()` and unique (user_id, provider, provider_connection_id).
- API: enroll (receives Teller enrollment from Connect, token encrypted with VP-009a), list, disconnect.
- Disconnect revokes at Teller where supported and deletes the local credential; minimal audit row only if DESIGN allows.
- Minimal frontend Connect launcher only if a Dashboard-owned task approves it; this task delivers API and tests.

## Out of Scope
Accounts, balances, transactions, sync, webhooks, dashboards. No cross-link to receipts.

## Dependencies
VP-009a, VP-009b COMPLETED. VP-009c recommended for verification.

## Requirements
1. `user_id` comes from the verified Foundation context only, never from the request body.
2. Credentials are never returned or logged.
3. Enrollment is idempotent on (user, provider, provider_connection_id).
4. Two-user isolation at API and database level.

## Acceptance Criteria
- [ ] Migration applies on a clean database; applied migrations untouched.
- [ ] User B cannot list, read or disconnect user A's connection.
- [ ] Duplicate enroll returns the same connection.
- [ ] Disconnect removes the credential.

## Testing Requirements
Migration, RLS, API authorization, isolation, redaction and idempotency tests with fake provider.

## Shared Resource Impact
Canonical identity: reads only. Cross-domain FK to profiles(id) requires Integration Review.

## Database Impact
NEW MIGRATION

## Contract Impact
NEW CONTRACT (Banking connection API)

## Security Considerations
Credentials encrypted with AAD (user, connection). Rate limit enroll.

## Financial Correctness Considerations
Not applicable.

## Blockers
Owner has not yet confirmed Teller certificate issuance from the Teller dashboard or the AWS region.
