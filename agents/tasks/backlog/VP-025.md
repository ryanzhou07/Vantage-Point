# VP-025 — Receivables filter and search UI

## Status
`BACKLOG`

## Owner
Receipt Agent (Integration/Review separate)

## Purpose
Give the owner a fast, accessible way to filter receivables by person or merchant, date range and paid status (and location once VP-024 lands), with paging that stays responsive. It must look like the rest of the dashboard.

## Scope
Frontend only, inside `apps/web/features/receipts/` (`ReceivablesPanel` and its CSS module). It consumes the VP-023 API.

### Match the existing UI
- Reuse `Button` (`primary` / `secondary`) and `Feedback` from `components/ui`. Reuse the row card pattern from `list.module.css`: `1px solid #c9d0ce` border, `.75rem` radius, white card, `1rem` padding, `.5rem` gaps. Use the existing tokens (`--vp-ink`, `--vp-muted`, `--vp-accent`, `--vp-border`); no new raw hex values.
- Keep the `.status`, `.meta` and `.outstanding` treatments. Add a method badge using the existing `.badge` style when `payment_method` is present (VP-021).
- No emoji or new icon sets; reuse `NavigationIcon` style only if an icon is needed.

### Filter bar
- A `<form role="search">` above the list with visible labels (never placeholder-only): "Search name or merchant", "From", "To", and a Status group "All / Owes you / Paid". After VP-024, add "Location".
- Dates use native `type="date"` inputs. All inputs are at least 16px so iOS does not zoom, and have 44px touch targets.
- Text inputs debounce 300 ms. Changing any filter resets the cursor and aborts the in-flight request (the panel already uses `AbortController`).
- Active filters render as chips that wrap onto multiple lines (never clip or hide overflow). Each chip has a remove button with an accessible name like "Remove filter: Paid". A "Clear all" button appears when any filter is active.
- Filters mirror to the URL query string so results can be deep-linked and the Back button works.

### Results and paging
- A polite live region announces the result: for example "12 receivables shown · $84.50 still owed", using the backend's filtered `outstanding_minor`. The frontend never computes totals.
- "Load more" button (not infinite scroll). It shows busy state, is disabled while loading, and moves focus to the first newly added row. Do not show a total count; use the "more available" signal from `next_cursor`.
- States: loading with reserved height (no layout shift), error with "Try again" that keeps the filters, empty-never-finalized (existing copy), and a separate no-results state: "No receivables match these filters" with a "Clear filters" button and a suggestion to widen the date range or shorten the search.
- Mobile first: single column, full-width inputs, wrapped chips, no horizontal scroll at 320px. Keep the existing 3px `#127967` focus ring. Respect `prefers-reduced-motion`; there are no required animations.

### UI/UX guidance applied
From the ui-ux-pro-max guideline search: "No Results" (show suggestions, not a blank or bare "0 results"), "Empty States" (explain and give an action), "Chip Collection Reflow" (wrap chips, do not clip), debounced search (no Enter required), and `scroll={false}` for pagination links so paging does not jump to the top.

## Out of Scope
Backend changes, API changes, saved filters, export, sorting controls, infinite scroll, Venmo/Zelle logic.

## Dependencies
VP-023 required. VP-021 optional (method badge). VP-024 optional (Location field). Build the location field and badge behind the presence of the data so the task can merge before them.

## Requirements
1. Every control has a visible label and keyboard operation; focus order follows the visual order.
2. Text contrast is at least 4.5:1 against its background.
3. No request fires for an invalid combination (for example `from` after `to`); show an inline error next to the field instead.
4. Stale responses never overwrite newer ones.
5. State survives a reload through the URL.

## Acceptance Criteria
- [ ] Typing a name filters results after about 300 ms and cancels the previous request.
- [ ] Date range, status and search combine and appear as removable chips; "Clear all" resets them.
- [ ] "Load more" appends rows without duplicates and keeps focus sensible.
- [ ] No-results and never-finalized states are visibly different and each offers an action.
- [ ] Reloading or sharing the URL restores the filters.
- [ ] Layout is usable at 320px, 375px and desktop widths with no horizontal page scroll.
- [ ] Screen readers hear the result count after each change.

## Testing Requirements
Component tests: debounce, abort of stale requests, URL sync, load more, chips, no-results versus empty, inline date-range error. Accessibility assertions on labels and the live region. Responsive check at 375px if the Playwright setup exists. Targeted vitest runs only.

## Shared Resource Impact
Dashboard navigation: NO. Shared contracts: consumes only.

## Security Considerations
Search text appears in the URL. It is filter text only, with no ids or tokens; keep it that way, and never put cursors in the URL.

## Financial Correctness Considerations
Amounts and totals come from the backend and are only formatted by the frontend (`money()`).
