## Requirements / scope
Read AGENTS.md, PROJECT.md authentication/Dashboard sections, DESIGN.md identity/authentication/presentation sections and this task before work.
1. Build a protected Settings page within the existing authenticated shell, reachable through navigation. Use a desktop settings sidebar and mobile-friendly section selector. Maintain current visual language: restrained cards, clear headings, generous spacing, readable forms and consistent reusable controls.
2. General: profile summary, display-name/contact-phone form previews, language/time-zone placeholders. Use existing real profile data read-only when available; never invent a user's details.
3. Appearance: Light/Dark/System visual option cards and display preference previews. Any selection is session-local preview only; do not install a new theme framework, claim persisted settings or change global application behavior.
4. Account: Google sign-in identity, current email read-only, future email-management and account-security placeholders. No functioning email/phone mutation, recovery or account deletion.
5. Plugins/Connections: separate Banking from payment contact details. Teller/Plaid show honest unavailable/empty states. Venmo/Zelle are future saved payment contact details, not live integrations; show clearly labeled form/removal previews with no save/disconnect calls or success claims. No fake connected banks or account balances.
6. Keep preview status clear at the page level; disabled future actions have useful descriptions. Forms may demonstrate local draft input but must not persist personal data in localStorage or send mutations.
7. Components are reusable, route files thin and spaced/readable. Keyboard navigation, focus indication, accessible labels, contrast and small-screen overflow are required.
8. Preserve the owner's earlier sign-in request: successful validated Google callback routes to fixed same-origin `/dashboard`; errors/cancellation remain actionable and no arbitrary return URL is introduced. Foundation owns this isolated change and the auth contract update after Dashboard finishes. Do not change PKCE, session handling or identity.
