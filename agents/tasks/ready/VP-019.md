# VP-019 — Finalize a receipt, receivables and receipt history

## Status
`READY`

## Owner
Receipt Agent (Integration/Review separate)

## Purpose
The owner finalizes a fully claimed, calculated split. It becomes an immutable snapshot, each non-owner participant gets a receivable (OWED), and the owner marks receivables PAID by hand. Finalized receipts stay in history.

## Scope
- `POST /api/v1/receipts/{id}/finalize {version}`: atomic DB function. Requires NEEDS_REVIEW, matching version, every item claimed, a current saved preview. Creates receivables from the saved shares for non-owner participants with amount > 0, sets FINALIZED, invalidates the active share session, writes an audit event.
- `GET /api/v1/receivables`, `POST /api/v1/receivables/{id}/paid {paid}`: owner-scoped list and manual paid toggle (PAID/OWED, `paid_at`).
- Summary list emits `amount_kind=FINALIZED` for finalized receipts and a real `outstanding_minor`.
- Finalized receipts cannot be edited, claimed or deleted.
- UI: Finalize button on the share step, read-only finalized view, receivables panel with paid toggles and outstanding total, history via the existing list.
- Fix: the summary list sent a query string that Foundation rejects; use path segments.

## Out of Scope
Reopen/revision workflow, participant reconfirmation, payment detection, Banking reconciliation, notifications.

## Requirements
1. Money is integer minor units; receivable = share total (items + tax + tip) from the saved preview. Frontend never computes it.
2. Owner-scoped everywhere; other owners get 404.
3. Finalization is all-or-nothing (single DB function under the receipt row lock).
4. Finalized data does not change; only receivable paid status changes, with audit events.

## Acceptance Criteria
- [ ] Unclaimed items, stale/missing preview, wrong version, or non-NEEDS_REVIEW block finalization.
- [ ] Receivables sum to the non-owner shares exactly; owner share creates none.
- [ ] Finalize invalidates the share link; claims and edits afterwards fail.
- [ ] Mark paid / unpaid works and updates outstanding.
- [ ] Finalized receipt appears in the list as Finalized and cannot be deleted.

## Testing Requirements
SQL assertions (finalize, blocks, receivable sums, paid toggle, delete block), Go route/ownership tests, component tests.

## Database Impact
Receipt-owned forward migration: FINALIZED status, `finalized_at`, `receivables`, event types, functions.

## Contract Impact
Extends RECEIPT_DRAFTS.md and RECEIPT_LIST.md.
