## Requirements
1. Follow DESIGN.md §§6–7, 26, 31, 38–43, 47, 49–53 and AGENTS.md shared ownership/security/testing/Git rules.
2. Provide one documented command to start the local Supabase stack, correctly configured Go API and web app; provide API-only, status, and data-preserving stop commands. The launcher must not require manual `source`/`export` every terminal session.
3. Save real local OAuth/backend configuration once in a Git-ignored, owner-controlled location outside disposable worktrees. Resolve this location consistently from separate worktrees; preserve existing values and file permissions, and never overwrite a configured file with an example.
4. Privately migrate/copy the owner's current configuration after verifying the target is empty/absent; explicitly separate browser-allowed public settings from private Google/backend settings. Only allowlisted public values may be materialized for the web app.
5. Discover/check repository-pinned Node/pnpm/Go/Supabase tools and give one-time setup guidance or scoped setup support. Do not rely only on temporary `/private/tmp` installations or silently upgrade versions. A user should not need to reconstruct PATH each startup.
6. Normal real Google development must fail clearly when credentials are missing; do not silently substitute the offline test client for user sign-in. Keep deterministic offline CI/tests explicitly supported and separate from real development mode.
7. Supply `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `WEB_ORIGIN` automatically to the local API command. The launcher must detect missing/invalid setting names before launching and explain the local start command without exposing values or bypassing authentication. Direct `go run` behavior remains unchanged.
8. Start must not reset the database or erase user/profile data. Detect existing listeners and managed processes safely; avoid duplicate services, unbounded waits, stale-PID killing and stopping unrelated processes/stacks. Handle partial start failure and signals with owned-process cleanup and useful status.
9. Detect stale Google provider configuration or document/apply the necessary data-preserving restart when saved credentials change; no need to re-enter credentials on each start.
10. Do not expose secrets in logs, process argument strings, Git, browser bundles, test evidence or printed Docker/CLI status. Capture/redact private CLI output; configuration is not financial authority.
11. Preserve the owner's currently running test environment until a coordinated startup smoke/restart is required. No live database resets or application-source edits. Coordinate any required restart of the current main preview.
