# VP-015b — QR/link sharing, participant join and live state

## Status
`READY` (owner approved 2026-10-28)

## Owner
Receipt Agent (Integration/Review separate)

## Purpose
Owner shows a QR code/link for the open session; participants scan, pick their name, and see live receipt state until the session expires.

## Scope
- Owner UI on the receipt: "Start split session", QR code + copyable link, visible countdown, close and restart buttons.
- Public join route consuming the share token: pick a participant name, receive a receipt-scoped participant authorization.
- Live updates via Supabase Realtime (DESIGN.md §24) for session state; clients refetch authoritative state from the Go API.
- On expiry, owner and participant screens show an "expired" state and stop accepting actions.

## Out of Scope
Claims/allocations and finalization (later task); push or webhook infrastructure.

## Dependencies
VP-015a COMPLETED.

## Requirements
1. Realtime is a notification only; expiry is decided by the backend, never the client countdown.
2. The token is read from the URL fragment or exchanged once, not logged or stored in localStorage.
3. Participants are receipt-scoped, not canonical users.
4. Mobile-first join screen; QR generated client-side from the link without a third-party call.

## Acceptance Criteria
- [ ] Scan/open link joins a valid session; expired or invalid token shows an actionable error.
- [ ] Session closes at 5 minutes and further requests are rejected.
- [ ] Realtime drop falls back to refetch without breaking the page.
- [ ] Responsive and keyboard/accessibility checks pass.

## Testing Requirements
Component tests, join/expiry E2E with a fake clock, realtime-fallback test.

## Financial Correctness Considerations
