# VP-016 — Receipts list with amounts owed

## Status
`REVIEW`

## Owner
Receipt Agent (Integration/Review separate)

## Purpose
A page listing the owner's receipts with status and what each participant owes, plus total outstanding.

## Scope
- Backend: paginated list endpoint returning receipt summary (merchant, date, status, total) and per-receipt owed amounts in integer minor units with currency; an outstanding total.
- Frontend: list under the existing Receipts route, row detail showing participant amounts, loading/empty/error states, responsive layout.

## Out of Scope
Receivable creation/finalization logic and marking paid (separate tasks); Banking reconciliation.

## Dependencies
VP-008 COMPLETED. Amounts owed are receivables created at finalization (DESIGN.md §Receivables); until a finalization task exists the list shows the VP-008 saved split preview, labeled as draft, and never as owed money.

## Requirements
1. Totals are computed by the backend; the frontend only formats.
2. Scoped to the authenticated owner; other users' receipts never appear.
3. Pagination bounded; no unbounded query.

## Acceptance Criteria
- [ ] Two-user isolation test passes.
- [ ] Draft and finalized amounts are visually distinct.
- [ ] Sums equal stored participant totals exactly (no floats).
- [ ] Empty, loading and error states render.

## Testing Requirements
API authorization/isolation, pagination, money-sum tests; component tests.

## Shared Resource Impact
Dashboard navigation: reuse existing Receipts entry.

## Database Impact
NONE expected (read-only queries)

## Contract Impact
NEW CONTRACT (Receipt list API)

## Security Considerations
Owner scoping from verified context only.

## Financial Correctness Considerations
Integer minor units end to end.

## Blockers
Finalization/receivable task not yet defined; owner to decide ordering.
