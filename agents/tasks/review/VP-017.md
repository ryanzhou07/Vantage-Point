# VP-017 — Teller Connect launcher and connected-institutions list

## Status
`REVIEW`

## Owner
Dashboard Agent (Integration/Review separate)

## Purpose
Let a signed-in user connect a bank through Teller Connect (Sandbox first) and see/disconnect connected institutions, using the VP-010 Banking connection API.

## Scope
- Settings > Plugins / Connections: replace the "Banking connections" placeholder with a Connect launcher, connected-institutions list and per-row Disconnect.
- Load `https://cdn.teller.io/connect/connect.js` (non-async) only when the user starts a connection; `TellerConnect.setup(...).open()` from a click.
- `onSuccess` posts `enrollment_id`, `access_token`, `institution_name` once to `POST /api/v1/banking/connections` with the Supabase bearer token; the token is never stored, logged or kept in state.
- Honest loading, empty, error (retry), missing-configuration, duplicate (already connected) and exit states.
- Config: `NEXT_PUBLIC_TELLER_APPLICATION_ID`, `NEXT_PUBLIC_TELLER_ENV` (default `sandbox`).

## Out of Scope
Accounts, balances, transactions (VP-011); any backend/migration change; real-bank use; Plaid.

## Dependencies
VP-010 (REVIEW, PR #19) connection API: enroll/list/disconnect.

## Requirements
1. No frontend user id is sent; identity comes from the bearer token.
2. No token persistence (no localStorage/state/logs).
3. Reuse `components/ui` and settings styles; mobile-first, keyboard accessible.
4. Show only API fields (institution name, status, created); no invented data.

## Acceptance Criteria
- [ ] Connect opens Teller Connect with configured application id/environment.
- [ ] Success enrolls and the institution appears; duplicate enroll shows it once.
- [ ] Exit and failure show safe messages and send nothing.
- [ ] Disconnect removes the row after the API confirms.
- [ ] Empty, loading, error and unconfigured states are truthful.

## Testing Requirements
Component tests with mocked `TellerConnect` global and mocked API: enroll success, exit, failure, duplicate, disconnect, empty, error. tsc, eslint, vitest.

## Shared Resource Impact
None. Reads Foundation `authClient` only.

## Database Impact
NONE

## Contract Impact
Consumes the VP-010 Banking connection API unchanged.

## Security Considerations
Application ID is public. Token sent once over the authenticated API. Safe error text only; no raw provider output.

## Financial Correctness Considerations
Not applicable (no money displayed).

## Blockers
VP-010 merge. Sandbox try-out also needs backend Teller secrets (ADR-009) and a Supabase session.
